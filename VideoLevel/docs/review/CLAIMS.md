# Claims, their realization in code, and their tests

Each entry covers one definition, lemma or theorem of
`docs/paper/sections/security.tex` (proofs in `security_appendix.tex`). It
gives a one-line restatement, the assumptions it uses, the code that realizes
those assumptions, and the tests that check the code side. Code paths are
relative to `VideoLevel/src/`, at commit `18c5123`. Test names are
`file::function` in `src/runtest/`. "No direct test" means the property is a
reduction or a probability bound that tests cannot check; the listed tests
then check only the functional preconditions.

Shared assumptions: M-SIS (ℓ∞ ≤ β = 8κB) and M-LWE (rank λ, n+1 samples,
ternary); SHA-256 and SHA3-256 collision resistance; ML-DSA-65 EUF-CMA. The
SHAKE-256 instances and SHA3-256 hedging are modelled as random oracles in
the classical ROM. No QROM claim is made.

## Gaps visible from this table

1. Lemma `lem:sim` and the reductions (`lem:row`, `lem:mlwe-instance`, `lem:fork`) have no executable check. That is expected, but nothing exercises the simulator's output distribution against real proofs on the toy set.
2. The uniformity of `G` (SampleInBall) and of the ternary sampler is argued, not tested statistically. Only the mask/response marginals have a chi-square test.
3. Production strength (|C| ≥ 2^256) is enforced only in `pins_from_registry`, not at the proof-verifier entry points (QUESTIONS Q12).
4. The canonical-digest lemma depends on code outside `src/lattice_zk/`, and the lattice tests replace it with a fake transport.
