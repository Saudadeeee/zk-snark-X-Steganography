## Capacity and security boundary

`prover.JindoParams.Size()/8` returned **550,249 bytes** for estimated Jindo commitment-plus-proof size. This is **not** serialized Buckler proof length; complete proof encoding/framing is absent in the pinned revision. It is about **51.05×** the 10,779-byte payload actually transported in the prior 3,000-frame Coastguard experiment, but the relation and videos differ. It signals a serious capacity problem, not a universal impossibility proof. No attempt to embed this Ringo proof into H.264 was made.

The fixture's context is a literal string, not a canonical video/session context; the payload is not linked to a public payload digest or the current application envelope. The custom commitment's hiding, binding, parameter security, and Fiat–Shamir adaptive-statement binding are not independently established. An application wrapper that derives public vectors does not itself prove transcript security. Ringo's in-memory `buckler.Proof` has no complete canonical wire serializer in this pinned source. Therefore the result establishes only runnable relation plumbing; it does **not** establish an acceptable lattice ZKP backend, video-only extraction, replay/expiry policy, realtime performance, or production readiness.

Plain `go test -race -count=1 ./...` failed with `fatal error: checkptr: converted pointer straddles multiple allocations` in dependency `math/crt/asm_ntt_amd64.go:112`, while `go test -race -gcflags=all=-d=checkptr=0 -count=1 ./...` passed on the complete current test (43.441 s reported package time). This is an upstream assembly/instrumentation limitation in this local run, not a clean race/checkptr bill of health. A Go reviewer confirmed the coefficientwise constraint shape and NTT equation, identified the original verifier-boundary defect, and flagged the missing payload/video relation and negative-test limits. The boundary defect was corrected and retested; independent cryptographic review remains absent.

**Decision:** retain this as a bounded research candidate. Do not register it as `lattice_zkp` or claim the active goal is complete. The next gate is a reviewed, concrete-security commitment and transcript relation for the canonical video/session statement, a canonical full-proof codec, and measured proof length against quality-validated CAVLC capacity on actual videos.
